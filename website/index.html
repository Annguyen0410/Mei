One process, four stations

Capture, plan, study, review — in one window

Mei is not a browser with a notes tab bolted on. It is organised around the loop that studying actually follows, and every station reads the same profile.

  1. 01

    Capture the page

    A tab, a highlight, a saved page or a quick note. It lands in the profile, not in a cloud clipboard.

  2. 02

    Give it a desk

    Name a research desk and link the tabs, notes, tasks and cards it belongs to — the same records, not copies.

  3. 03

    Plan the week

    Courses, deadlines, focus blocks and study sessions sit on one week grid, with the next step surfaced on Home.

  4. 04

    Review on a schedule

    Cards come back on an SM-2 interval. Grades move the interval; the deck and the week both learn from it.

The browser

Chromium 140, arranged for reading

Real browsing on Qt WebEngine 6.11 — tabs, tab groups, split view, reader tools, downloads, incognito profiles and optional web panels. The difference is what the chrome is willing to hold for you.

Engine
Chromium 140.0.7339.225 on Qt 6.11.0, packaged with PyInstaller 6.19.0. Pinned, and checked in CI.
Tabs
Groups, split view, hibernation for the ones you are not reading, and saved tab sets you can restore later.
Reading
Reader mode that strips the page, plus a workspace that keeps the source beside the note you wrote about it.
Protections
Ad and tracker filtering, HTTPS-only policy, Client Hints and cookie controls, per-origin permissions.
Autofill
Saved logins fill only when you ask (Ctrl+Shift+L), and only into a form that submits by POST — a password never lands in a URL.

Research desks

A desk is a link table, not a folder of duplicates

Save your open tabs as a named desk, then point it at the notes, tasks, saved pages and flashcards that already exist. Mei stores one typed edge per link, so a note edited from the desk is the same note the Personal hub shows.

Personal workspace

The part that turns reading into a week

Notes with wiki links, quick tasks, a calendar, boards, saved pages, the Weekly Plan and SM-2 review. Each one is a view over the profile — not a separate app with its own database to keep in sync.

  • Notes save as you type, with categories, wiki-style links and a word count that is honest about length.
  • Planner rows pour into a study session: minutes are credited once, and the focus block records where they came from.
  • Review grades a card, moves its interval, and reports the deck's due count on the nav badge.
  • Rest — your records stay yours: everything is JSON on disk, written atomically, with a versioned migration step per store.

AI workspace

Retrieval first, provider second, context by consent

Mei searches your own profile before it asks a model anything: BM25 by default, optional embeddings when you have them. The provider is a setting, not a dependency — and page content is treated as untrusted input, never as instructions.

Where a request goes depends entirely on the provider you configure.
Provider Runs What leaves the device
Ollama local Nothing, as long as the endpoint is on your machine or your own network.
llama.cpp server local Nothing, to the same extent — Mei sends the request to the endpoint you set.
OpenRouter remote The prompt and the context you selected, sent to that provider. Reviewed by you, per request.

Context controls

Browser context and research context are separate switches. Private windows are excluded from both, and the prompt shows what was attached before it is sent.

Agents and slash commands

Commands run against the same stores the UI does — summarize the active page, save a tab set, ask the deck what is due. Nothing is hidden behind a second API.

What Mei will not claim

No model is bundled, no benchmark is invented, and “local” never means “private by default” — it means the request did not leave the machine you configured.

The study loop

One recommendation, four surfaces

The flow layer stores nothing. It reads the agenda, the deck, the captures and the pour journal, then answers one question — what do I do next — for Home, the planner, the Morning Brief and slash commands alike.

  1. Read

    Capture the page that mattered, with the tab still attached.

  2. Distil

    Write the note, then the card. The card remembers which note it came from.

  3. Pour

    Study a planner row in a focus block; minutes are credited once.

  4. Return

    Review what is due, then read the week back: streak, minutes, untouched rows.

Privacy and data integrity

Local-first, described precisely

Marketing loves the word “encrypted”. Mei's actual model is more specific than that, so this section says exactly what protects what.

No account, no hosted service
Mei runs without signing in. Nothing is uploaded to a Mei server because there is no Mei server in the path.
One profile, plain files
Tabs, history, notes, planner, cards and links live under the profile folder, written atomically and migrated with a version per store.
Secrets are kept apart
The AI key, Google token cache, sync token, bridge token and proxy password sit in secrets.dat, protected with Windows DPAPI for the signed-in user.
Secrets stay out of copies
secrets.dat is deliberately excluded from backups, folder and self-hosted sync, and diagnostics bundles.
Backups are verified
Versioned backups, a staged Restore Center with rollback, Storage Health, record-level restore and a Sync Conflicts archive.
Opt-in backup encryption
Encrypted backups use an AES-256-GCM container with a scrypt-derived key. Scheduled backups stay unencrypted because Mei never stores that password.

What Mei does not promise

  • A passcode gates workspaces; it does not encrypt every profile file at rest.
  • Local storage is not encryption. File permissions are not encryption either.
  • On platforms other than Windows, secrets use owner-only file permissions and Mei says so in the UI.
  • A remote AI provider receives the context you select for that request.
  • The local-network bridge speaks plain HTTP; Mei warns before LAN mode is enabled.

Optional integrations

Nothing here is required to use Mei

Each integration is configured by you, and each one is off until you turn it on.

  • Android bridge

    Pair a phone on loopback by default. LAN mode speaks plain HTTP, warns first, and rotating the token disconnects everything paired with the old one.

  • Mei browser extension

    Requests activeTab rather than access to all sites, and talks to the app over the same bridge token.

  • Folder sync

    Sync a profile bundle through a folder you choose, with conflict archives instead of silent overwrites.

  • Self-hosted sync

    A token-protected endpoint you run. Mei stores the token in secrets.dat, not in the profile JSON.

  • Google integration

    Optional, with the token cache protected by DPAPI and excluded from backups and diagnostics.

  • Mei-1.0.2.0-web_support.zipCompanion archive with the local web workspaces. Extract beside Mei.exe.
  • update.jsonThe channel file the app reads to offer an in-place update.
  • RELEASE_BODY.mdRelease notes for this tag, also in docs/CHANGELOG.md.

Install

  1. Download MeiSetup.exe from the release page and run it.
  2. If you use the portable build, unpack web_support beside Mei.exe and keep the folder where it is.
  3. Start Mei. The profile is created under runtime_data/profiles next to the executable, not in place of it.
  4. Back the profile folder up before moving to another machine. Replacing the app never replaces the profile.

Questions

Asked without the marketing filter

Does Mei need an account or send my data anywhere?

No account, and no Mei-hosted data service. The profile is a folder on your disk. Requests leave the machine only when you configure something that makes them: a remote AI endpoint, folder sync to a location you picked, or the Android bridge.

Is my profile encrypted?

Not by default. A passcode gates workspaces but does not encrypt every file. What is protected: the secrets file (secrets.dat) uses DPAPI on Windows and owner-only permissions elsewhere, and encrypted backups are available as an opt-in AES-256-GCM container. The rest of the profile is JSON on disk — back it up, and keep the machine's disk encryption on if that matters to you.

Can I use Mei completely offline?

Yes for browsing, notes, planning and review. The AI workspace runs offline with a local Ollama or llama.cpp endpoint; no model is bundled with the app. OpenRouter is remote by definition.

What happens to saved passwords?

Automatic save-on-login is suspended while the credential bridge is rebuilt (ADR-0006); the vault and manual entries still work. Filling a saved login is an explicit action — Ctrl+Shift+L — and the fill refuses any form that would submit by GET, so a password cannot end up in the address bar.

Which platforms are supported?

Windows 10 and 11, built from Python 3.11 with PyQt6 6.11.0. The source runs on other desktop platforms, but releases published here are Windows builds; the mobile bridge pairs a phone browser, it is not an Android app release.

Is it free? Can I read the source?

Yes. Mei is MIT licensed on GitHub, and CI runs the full test suite, the lint gate, the engine-version gate and the day/night theme checks on every push.
